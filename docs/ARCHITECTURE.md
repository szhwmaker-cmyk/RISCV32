# RV32E SoC 系统架构设计文档

**项目名称**: RV32E 五级流水线处理器 SoC
**版本**: 1.0
**最后更新**: 2025-11-04

---

## 1. 系统概述

本项目实现一个基于 RISC-V RV32E 指令集的五级流水线处理器 SoC 系统。系统具备从 SPI Flash 启动的能力，并集成了完整的外设子系统，适用于嵌入式应用场景。

### 1.1 核心特性

- **处理器核心**: RV32E 五级流水线（IF → ID → EX → MEM → WB）
- **指令集**: RV32E 基础整数指令集（16 个通用寄存器）
- **启动方式**: SPI Flash Boot（支持 XIP 或 Boot Loader 模式）
- **总线协议**: Wishbone B4 Pipeline
- **外设系统**: UART, GPIO, SPI Master, I2C Master
- **存储器**: 64KB SRAM

### 2.1 主要组件说明

1. **处理器核心**: 实现完整的 RV32E 指令集，支持数据冒险转发和控制冒险处理
2. **Wishbone 互联**: 连接处理器和所有外设，提供统一的访问接口
3. **SPI Flash 控制器**: 支持启动代码加载和运行时数据访问
4. **外设集合**: 提供标准的串口、GPIO、SPI 和 I2C 通信接口

## 3. 总线架构设计

### 3.1 总线协议选择：Wishbone B4 Pipeline

**选择理由**:

1. **简单性**: Wishbone 协议规范清晰，信号定义明确，易于实现和调试
2. **开源友好**: 作为开源总线标准，拥有大量参考实现和社区支持
3. **流水线支持**: Wishbone B4 支持流水线传输，可提高总线利用率
4. **灵活性**: 支持多主多从配置，便于系统扩展
5. **时序要求**: 相比 AHB-Lite，时序要求更宽松，更适合 FPGA 实现

**对比 AHB-Lite**:

| 特性 | Wishbone B4 | AHB-Lite |
|------|-------------|----------|
| 复杂度 | 低 | 中等 |
| 握手机制 | CYC + STB + ACK | HREADY |
| 地址相位 | 单相位 | 双相位 |
| 流水线支持 | 原生支持 | 需要扩展 |
| 开源生态 | 丰富 | 较少 |
| 学习曲线 | 平缓 | 较陡 |

### 3.2 Wishbone 接口信号定义

```scala
class WishboneIO extends Bundle {
  // Master → Slave 信号
  val adr_o  = Output(UInt(32.W))   // 地址线
  val dat_o  = Output(UInt(32.W))   // 写数据
  val we_o   = Output(Bool())       // 写使能 (1=写, 0=读)
  val sel_o  = Output(UInt(4.W))    // 字节选择 (4 bits for 32-bit bus)
  val stb_o  = Output(Bool())       // Strobe 信号 (传输有效)
  val cyc_o  = Output(Bool())       // Cycle 信号 (总线周期有效)

  // Slave → Master 信号
  val dat_i  = Input(UInt(32.W))    // 读数据
  val ack_i  = Input(Bool())        // 应答信号 (传输完成)
}
```

### 3.3 总线互联拓扑

采用 **共享总线 + 仲裁器** 的结构：

- **单主设备**: 处理器核心（未来可扩展 DMA）
- **多从设备**: SPI Flash, UART, GPIO, SPI, I2C, RAM
- **地址译码**: 基于地址范围的自动路由
- **仲裁策略**: 固定优先级（当前单主设备无需仲裁）

## 4. 地址空间映射

### 4.1 完整地址映射表

| 设备 | 基地址 | 结束地址 | 大小 | 描述 |
|------|--------|---------|------|------|
| **SPI Flash** | `0x1000_0000` | `0x1FFF_FFFF` | 256 MB | SPI Flash 访问空间（XIP 或加载） |
| **UART** | `0x2000_0000` | `0x2000_FFFF` | 64 KB | UART 控制器寄存器 |
| **GPIO** | `0x2001_0000` | `0x2001_FFFF` | 64 KB | GPIO 控制器寄存器 |
| **SPI Master** | `0x2002_0000` | `0x2002_FFFF` | 64 KB | SPI 主控制器寄存器 |
| **I2C Master** | `0x2003_0000` | `0x2003_FFFF` | 64 KB | I2C 主控制器寄存器 |
| **RAM** | `0x8000_0000` | `0x8FFF_FFFF` | 256 MB | SRAM 空间（实际 64KB） |

### 4.2 外设寄存器详细映射

#### UART 寄存器 (Base: 0x2000_0000)
| 偏移 | 名称 | 描述 |
|------|------|------|
| 0x00 | TXDATA | 发送数据寄存器（写） |
| 0x04 | RXDATA | 接收数据寄存器（读） |
| 0x08 | STATUS | 状态：[7:0] = {tx_full, tx_empty, rx_valid, ...} |
| 0x0C | BAUD   | 波特率分频值 |
| 0x10 | CTRL   | 控制：[1:0] = {tx_en, rx_en} |

#### GPIO 寄存器 (Base: 0x2001_0000)
| 偏移 | 名称 | 描述 |
|------|------|------|
| 0x00 | DATA_IN  | 输入数据（只读） |
| 0x04 | DATA_OUT | 输出数据（读写） |
| 0x08 | DIR      | 方向控制（0=输入, 1=输出） |
| 0x0C | OE       | 输出使能 |

#### SPI Flash 控制器 (Base: SPI Flash 区域内存映射)
| 偏移 | 名称 | 描述 |
|------|------|------|
| 0x00 | CTRL | 控制：{start, busy, done} |
| 0x04 | DIV  | SPI 时钟分频 |
| 0x08 | ADDR | Flash 地址 |
| 0x0C | DATA | 读取数据 |
| 0x10 | CMD  | SPI 命令 |

## 5. 处理器核心架构

### 5.1 五级流水线设计

```
┌─────┐    ┌─────┐    ┌─────┐    ┌─────┐    ┌─────┐
│ IF  │ -> │ ID  │ -> │ EX  │ -> │ MEM │ -> │ WB  │
└─────┘    └─────┘    └─────┘    └─────┘    └─────┘
  T1         T2         T3         T4         T5
```

#### 阶段功能分解

1. **IF (Instruction Fetch) - 取指阶段**
   - PC 管理（递增、跳转）
   - 通过 I-Memory Port 从存储器读取指令
   - 输出：PC, Instruction

2. **ID (Instruction Decode) - 译码阶段**
   - 指令解码（识别 R/I/S/B/U/J 型指令）
   - 读取寄存器文件（rs1, rs2）
   - 立即数生成和符号扩展
   - 生成控制信号
   - 输出：ALU 操作码、操作数、控制信号

3. **EX (Execute) - 执行阶段**
   - ALU 运算
   - 分支条件判断
   - 分支/跳转目标地址计算
   - 输出：ALU 结果、分支决策、目标地址

4. **MEM (Memory Access) - 访存阶段**
   - 通过 D-Memory Port 访问数据存储器
   - 处理 LOAD/STORE 指令
   - 支持字节、半字、字访问
   - 输出：内存读取数据

5. **WB (Write Back) - 写回阶段**
   - 选择写回数据源（ALU / Memory / PC+4）
   - 写入寄存器文件

### 5.2 流水线寄存器

| 寄存器 | 包含信息 |
|--------|---------|
| IF/ID  | PC, Instruction |
| ID/EX  | PC, RegData(rs1, rs2), Immediate, Control Signals, Dest Reg |
| EX/MEM | ALU Result, RegData(rs2), Control Signals, Dest Reg |
| MEM/WB | Memory Data, ALU Result, Control Signals, Dest Reg |

## 6. 冒险处理策略

### 6.1 数据冒险 (Data Hazards)

#### 6.1.1 RAW (Read After Write) 冒险

**场景示例**:
```assembly
add x1, x2, x3    # WB 阶段写 x1
sub x4, x1, x5    # ID 阶段读 x1 (冒险！)
```

**解决方案：数据转发 (Forwarding)**

转发路径：
1. **EX 转发**: EX/MEM → EX 阶段
2. **MEM 转发**: MEM/WB → EX 阶段
3. **WB 转发**: WB → ID 阶段（寄存器文件旁路）

**转发逻辑**:
```scala
// EX 转发条件
if (EX_MEM.regWrite && EX_MEM.rd != 0 && EX_MEM.rd == ID_EX.rs1)
  forward_A = EX_MEM.aluResult

// MEM 转发条件
if (MEM_WB.regWrite && MEM_WB.rd != 0 && MEM_WB.rd == ID_EX.rs1)
  forward_A = MEM_WB.writeData
```

#### 6.1.2 LOAD-USE 冒险

**场景示例**:
```assembly
lw  x1, 0(x2)     # MEM 阶段才获得数据
add x3, x1, x4    # EX 阶段需要 x1 (无法转发！)
```

**解决方案：流水线暂停 (Stall)**

- 检测到 LOAD 指令后紧跟使用该寄存器的指令时，插入 1 个气泡（NOP）
- 暂停 IF 和 ID 阶段，ID/EX 插入 NOP

**检测逻辑**:
```scala
val load_use_hazard =
  ID_EX.memRead &&
  (ID_EX.rd == IF_ID.rs1 || ID_EX.rd == IF_ID.rs2)

when (load_use_hazard) {
  stall_IF := true
  stall_ID := true
  flush_EX := true
}
```

### 6.2 控制冒险 (Control Hazards)

#### 6.2.1 分支预测策略

采用 **静态预测 - 总是不跳转** 方案：
- 默认按顺序取指（PC + 4）
- 分支判断在 EX 阶段完成
- 预测错误时 flush 已取的指令

#### 6.2.2 分支错误处理

当 EX 阶段检测到分支跳转时：
1. Flush IF 和 ID 阶段的指令（设为 NOP）
2. 更新 PC 为分支目标地址
3. 重新取指

**性能损失**: 每次分支跳转损失 2 个周期

**优化方向**（未来改进）:
- 提前到 ID 阶段进行分支判断（需要增加比较器）
- 实现分支目标缓冲（BTB）
- 动态分支预测器

## 7. SPI Flash 启动系统

### 7.1 启动流程

```
  ┌──────┐
  │RESET │
  └───┬──┘
      │
      v
  ┌────────────┐
  │ INIT_SPI   │  配置 SPI Flash 控制器
  └─────┬──────┘
        │
        v
  ┌──────────────┐
  │ READ_FLASH   │  从 Flash 读取启动代码
  └──────┬───────┘
         │
         v
  ┌──────────────┐
  │  LOAD_RAM    │  将代码复制到 RAM
  └──────┬───────┘
         │
         v
  ┌──────────────┐
  │  BOOT_DONE   │  设置 PC 到程序入口
  └──────┬───────┘
         │
         v
  ┌──────────────┐
  │    RUN       │  处理器开始执行用户代码
  └──────────────┘
```

### 7.2 两种启动模式

#### 模式 A: XIP (Execute In Place)
- **优点**: 简单，无需 RAM
- **缺点**: 性能较低（SPI 访问慢）
- **适用**: 代码量小、对性能要求不高的场景

#### 模式 B: Boot Loader（推荐）
- **流程**:
  1. 处理器复位后从 SPI Flash 地址 `0x1000_0000` 开始执行
  2. Boot ROM 中的 Loader 代码将 Flash 中的用户程序复制到 RAM
  3. 跳转到 RAM 地址 `0x8000_0000` 执行用户代码
- **优点**: 执行速度快
- **缺点**: 需要 RAM，启动时间稍长

### 7.3 SPI Flash 读取时序

支持标准 SPI 模式和 Fast Read 命令：

```
Fast Read 命令 (0x0B):
┌─────┬─────────┬──────┬─────────┬─────────┬─────────┐
│ CMD │ ADDR[23]│DUMMY │ DATA[0] │ DATA[1] │ ...     │
│ 8bit│  24bit  │ 8bit │  8bit   │  8bit   │         │
└─────┴─────────┴──────┴─────────┴─────────┴─────────┘
```

## 8. 系统时序参数

### 8.1 时钟配置

- **系统时钟**: 50 MHz
- **SPI 时钟**: 可配置分频（默认 50MHz / 4 = 12.5 MHz）
- **UART 波特率**: 115200 bps（分频值 = 50M / 115200 ≈ 434）
- **I2C 时钟**: 100 kHz (标准模式) 或 400 kHz (快速模式)

### 8.2 复位策略

- **类型**: 同步复位（Synchronous Reset）
- **极性**: 高电平有效
- **持续时间**: 至少 10 个时钟周期
- **复位行为**:
  - PC → `0x1000_0000`
  - 所有寄存器清零
  - 流水线清空
  - 外设复位到默认状态

## 9. 性能评估

### 9.1 理论性能

- **最大频率**: 50 MHz (FPGA 实现目标)
- **理想 CPI**: 1.0 (无冒险时每周期执行一条指令)
- **实际 CPI**: 约 1.3 - 1.5 (考虑冒险和分支预测失败)

### 9.2 冒险开销

| 冒险类型 | 频率 | 惩罚周期 | 平均开销 |
|---------|------|---------|---------|
| LOAD-USE | 15% | 1 | 0.15 |
| 分支跳转 | 10% | 2 | 0.20 |
| 总计 | - | - | **~0.35** |

**估算 CPI**: 1.0 + 0.35 = **1.35**

### 9.3 启动时间

以 64KB 程序为例：
- Flash 读取速度: 12.5 MHz SPI ≈ 1.5 MB/s
- 传输时间: 64KB / 1.5MB/s ≈ **43 ms**
